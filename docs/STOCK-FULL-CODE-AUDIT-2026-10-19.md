# 全功能代码审查与 A 股前后端差距分析

审查日期：2026-10-19；本轮只读数据库观测时刻为北京时间 10:32。本文是审查交付，不是修复完成记录。

## 1. 结论和边界

**全系统状态：部分完成，不能按“两市场功能对等、题目二完整、可正式上线”验收。**

当前实现是期货主体，加上已接通的 A 股板块浏览、日线图表、固定因子研究、后台研究报告和受限主板日线回放。不是所有股票菜单都为空，但也不是切换市场后就有完整的另一套产品。

本轮四个工作包：入口与前端状态审查；数据/研究/撮合审查；共享认证/期货/Agent 复用边界审查；现有全量测试与真实本地只读覆盖核实。覆盖主导航、认证、股票 API、关键模型/服务/worker/测试；管理员页面核对其职责和股票运维缺口，不声称逐行证明所有管理功能安全。没有新增交易任务、研究任务、QA 用户，没有改用户浏览器或服务状态，没有主动请求 Teajoin/付费模型。

题目二按用户提供的《金融信息系统课程设计任务书(1).docx》原文逐项核对；文档内容仅作为需求材料，不作为执行指令。用户要求只模拟及日线回放，因此分钟/实时/券商接口不是本轮补齐的前置条件。tick 项目可复用视觉和交互，不代表可从日 OHLCV 生成真实分时或分价成交量。

## 2. 优先缺陷：先修这些，再复制期货模块

优先级：P1 为隔离、授权、核心正确性或发布阻断；P2 为明显业务/可用性问题。未发生的资金损失、真实越权和外部攻击不作推断。

### F01 / P1：切换市场的旧请求能污染新登录会话

- 位置：`frontend/src/stores/auth.ts:113`，成功回写 `:122`，失败回滚 `:130`。
- `switchMarket` 保存整个旧 user；响应时没有核对原用户、token、会话代次和请求顺序。请求失败可在退出后恢复旧 user，或在 B 登录后将 A 的资料恢复到 B 的 token 旁边；旧成功响应也能更改新会话市场。
- 证据：对实际 TS store 转译后用内存 localStorage、延迟 Promise、合成 A/B 会话复现。不是已经证实后端允许 A 的资源以 B 身份访问。
- 修复边界：会话代次/序号校验；仅同会话回滚对应字段；抛弃退出/换号后的陈旧结果；覆盖连续切换逆序返回、退出、重新登录。

### F02 / P1：AI 可以自己声称“用户确认”

- 位置：`backend/app/services/ai/gateway.py:174`—192，`backend/app/services/ai/tools/paper/defs.py:40`。
- 模型生成参数 `confirmed` 被 `bool(...)` 用作允许模拟写操作的依据；没有用户/规范化参数/有效期绑定的服务端确认凭据。`"false"` 字符串同样会被当成 True。
- 对真实解析片段的离线探针确认了上述真假值行为；没有真实下单或付费调用。即使用户未启用自由交易，模型也能绕过逐笔 UI 确认。
- 修复边界：先创建结构化待确认动作；由真实用户端提交一次性确认；服务端绑定用户、市场、登录盘、参数 hash、有效期及幂等键。确认后重新鉴权，不允许模型提供自己的批准。

### F03 / P1：聊天工具遗漏登录盘，AI 任务取价也遗漏登录盘

- 聊天链路：`backend/app/api/ai_chat.py:404` → gateway/registry → `backend/app/services/ai/tools/paper/exec.py:93`，未传 `trading_mode`；`paper/trading_svc.py:52` 默认 live。查询、撤单也存在同类遗漏。
- 自动任务：`backend/app/services/ai_trading/engine.py:280`、`:328`、`:745` 获取 K 线/参考价时未传 task 模式，而 `ai_trading/core/execute.py:131` 下单正确传了 mode。虚拟任务可能按 live 数据决策、向 virtual 账户下单。
- 对实际 `_place` AST 配以边界替身，捕获 12 个位置参数，落到默认 live。没有写真实账本。
- **这里 live/virtual 都是项目模拟体系的分盘；不是发现券商实盘交易或跨用户越权。**
- 修复边界：统一显式 ExecutionContext；所有读写/缓存/推送/取价都透传 user/resource/market/mode；资金写接口不能悄悄使用默认盘。股票入口不能仅靠隐藏前端替代后端范围校验。

### F04 / P1：五年研究窗口被当前安全上限直接拒绝

- 位置：`backend/app/services/stock_factors/snapshots.py:23`、`:148`—150。
- 本地真实只读预检 2021-10-16 至 2026-10-16：300 只、1,212 个观测日期、2,302,800 面板格；超过 2,000,000，返回 `over_limit`。同时还有 8,931 个证券×观测日缺价格。
- 没有跑实际五年回测，不能把“预检很快”说成“300 股×5 年 5 分钟内完成”。
- 当前加载器不随所选因子减少财务/估值面板。应按依赖列、股票池、分批/版本缓存优化，并给真实数据做缺口处理和资源实测；不能简单解除安全限制。

### F05 / P1：旧同步研究 API 可绕开新后台研究约束

- 位置：`backend/app/api/stock_factors.py:51`—52、`:87`、`:102`；旧引擎 `backend/app/services/stock_factors/engine.py:105`、`:142`。
- 旧分析/回测端点仍注册；登录用户可直接在 HTTP 中加载并执行，未经过新任务队列的快照容量、幂等、取消、持久结果和执行预算。部分旧加载查询没有数量边界。
- 修复边界：兼容旧调用方的适配/版本策略，让旧入口归一到受控业务服务；长任务用异步查询状态。不能靠新前端先检查来保护旧接口，也不能为了跑五年绕回旧接口。

### F06 / P1：内容指纹不等于不可变数据版本，历史时点和幸存者偏差未闭环

- 位置：`backend/app/services/stock_factors/snapshots.py:151`、`:169`、`:179`—184；`backend/app/models/stock.py:87`；`backend/app/data/stock_history.py:62`。
- 研究保存了参数、结果、输入指纹和 manifest，但没有保存可按版本重新读出的完整输入。manifest 明确 `immutable_archive=False`、`point_in_time_certified=False`。保存旧报告不等于用相同数据版本重算。
- 旧 qfq 锚点未版本化；财报唯一键保留单一修订视图；行业/证券状态主要是当前值，历史退市/成分/状态不完整。
- 已有修复应保留：财报严格公告后可用、信号滞后一日；缺价不填假价；旧导入器现会拒绝小数手和已有股票追加新锚点。不能再说当前导入器会无条件追加混复权。
- 修复边界：raw bar、Decimal 量、复权因子/锚点、公告和实际可得时间、修订版本、历史证券池/状态的兼容扩展；版本化 reader；受控迁移保留旧有效记录。缺少历史证据时标未认证，不能补造时间戳。

### F07 / P1：生产启动路径仍执行遗留 DDL 和数据变更

- 位置：`backend/app/main.py:959`—966 在生产也调用 `_init_tables`；`:153` 更新任务；`:170` 删除旧列；`:734` 起处理约束/索引及来源回填。
- 股票独立 001—006 迁移已存在，但全局遗留启动逻辑并未因此变成版本化迁移。存在多进程竞争、锁、非兼容删除和回退困难。
- 修复边界：逐条梳理遗留操作后转成有版本/锁/前置检查的迁移；启动只检查兼容性。不得本轮临时执行 DDL 来“修复”；先准备备份、顺序和前向恢复方案。

### F08 / P2：个人资料是占位内容，保存按钮没有持久化

- 位置：`frontend/src/app/(main)/profile/page.tsx:73`、`:88`、`:107`、`:112`、`:117`、`:123`。
- 用户名、邮箱、ID、手机号、注册日期硬编码，“已认证”无真实依据，保存只退出编辑。不是行情造价，但属于未标注的假资料和无效操作。
- 后端 `backend/app/api/users.py:41` 已有本人资料更新能力，前端未接。用户名编辑能力需服从实际 schema，不能伪装可写。
- 修复边界：真实当前用户读写、唯一冲突反馈、取消恢复/失败保留、按权限可编辑字段；没有认证事实就不显示已认证；头像未接通时禁用并说明。

### F09 / P2：期货账户摘要把未实现和当日盈亏固定为零

- 位置：`backend/app/services/paper/account_svc.py:269`、`:285`—286；前端 `frontend/src/components/dashboard/asset-summary.tsx:55`、`:65` 直接展示。
- 总权益只取余额加冻结保证金，没有按账户未平仓头寸统一估值。部分持仓 UI 另算浮盈，不能说所有持仓页面都错，但摘要和风险口径不一致。
- 修复边界：服务端统一估值、参考价时间和新鲜度、结算/当日基准；无价时返回不可估值及原因，不能返回虚假的 0。不可照抄给 A 股。

### F10 / P2：改密后旧 token 没有服务端撤销机制

- 位置：`backend/app/api/users.py:93`—95；`backend/app/core/auth.py:28`；`backend/app/core/deps.py:75`。
- 改密仅更新哈希；认证未核对安全版本/会话撤销记录。前端本地 logout 不会使已发 token 全局失效。没有本轮修改真实用户密码进行在线验证，属于代码确认的机制缺口。
- 修复边界：带兼容迁移的会话/安全版本、刷新轮换、改密撤销策略及跨端用例，不得只改提示文案。

| 资产 `/assets` | 回放资产 tab、自定义开户金额，非期货保证金 | 股数/现金/持仓市值/总资产一致，费用明细可追踪 | 股票独立账本/估值；如要开户后加减模拟资金，新增受控流水功能，不能借期货充值混账 |
| 历史 `/history` | 本人研究报告持久化可重开 | 两组对齐比较、下载、版本说明、不可复算原因 | 按同一数据版本重算与校验；归属/分页/取消/失败留存；结果 JSON 不等于所有格式导出已实现 |
| 个人中心 `/profile` | 信息/显示/安全入口可用，但个人资料占位 | 接真实资料更新、认证事实，改密状态准确 | 会话安全与唯一性；不为模拟产品强加真实券商账户/KYC |
| AI 设置 `/ai-settings`、Skills | 共享模型配置/技能/工具能力存在；股票工具适配不完整 | 不暴露不可用期货工具；修 Skills 路由矛盾；明确共享还是分市场 | 能力标签/工具权限/检索与记忆 scope、版本/预算；秘密仅服务端管理，不回显 |
| 消息 `/messages` | 股票阻断；期货不是全假消息，有实际通知服务 | 股票研究/回放真实事件、已读/失败/跳转 | user+market+mode+资源/版本事件、幂等投递/推送和分页；禁止造消息填页面 |
| 管理端 | 原用户/模型/渠道/期货配置等存在，股票运维多为内部 CLI/状态接口 | 数据缺口/版本/归档失败/恢复审计只读视图及受控操作 | 权限、恢复预算/来源 hash、操作审计、发布健康/告警；原 006 CLI 不是完整运维台 |

三处股票研究入口复用服务是合理的，不必为了菜单数拆三套引擎；但应让入口角色清楚，不能以三条路由计为三套能力。股票资产/持仓/委托共用一个回放状态也是合理的，前提是每一入口信息完整、可查历史、范围明确。

## 5. 题目二逐项对照

| 原要求 | 当前状态 | 验收缺口 |
|---|---|---|

| 300股×5年、月调仓 <5分钟 | 未达到验收；当前五年被预检拒绝 | 不去掉保护前提下资源优化；真实数据集/硬件/峰值内存/耗时和结果一致性实测 |

扩展 ML/正交化等不是当前先决项。日线产品不必为了外观补造实时数据。国际黄金/白银仍缺现渠道合约单位、日界/日历和授权证明，不应并入人民币期货模拟结算；不在本轮新增适配。

## 6. 可以复用期货的什么，不能照抄什么

可以复用组件壳、图表交互、任务状态 UI、Schema 草稿确认交互、幂等/事务模式、本人资源权限模式、纯指标算法、通知基础设施。继续使用现有技术栈，不需要拆服务或换框架。

必须股票专用：证券标识和历史池；raw/qfq 和除权分红；整手/T+1/停牌/涨跌停/逐日状态；股票现金账本、费用税率；研究/回放时钟；模型工具和提示词；基准和估值字段。期货保证金、开平、多空、连续合约换月语义不适用。

期货自然语言功能目前是确定性规则解析加严格 schema，确认后回填已有表单、任务草稿 autoStart=false，主动模型调用为零。这是好的安全起点，但不能宣传为理解任意自然语言策略或已能新建 A 股 AI 任务。

1. **身份与用户页面垂直修复**：switchMarket 会话 race 的先红后绿回归；真实个人资料读写；改密撤销设计/兼容迁移与隔离 PG 验证。验收换号/切市场/保存后刷新不串号、假资料消失。

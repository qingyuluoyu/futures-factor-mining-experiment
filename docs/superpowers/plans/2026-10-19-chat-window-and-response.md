# 聊天窗口与无响应修复 Implementation Plan

**Goal:** 修复用户截图中的聊天窗口过窄/截断、供应商限流原文和消息无响应；不绕过上游TPM/RPM，不改密钥、不自动重试付费调用。

**Architecture:** 沿用浮窗Zustand、SSE、FastAPI和现有Provider。只做兼容扩展，无表结构变更。三个完整工作包顺序执行、先红后绿并逐包回顾。

## C02 上游失败可解释
- [x] OpenAI Provider对HTTP429、认证/余额/不可用、超时、SSE内error和usage-only包分别处理；拒绝向用户透传任意上游原文，保留标准化错误码、重试建议，不自动重试或切换源。
- [x] 明确每请求输出token上限4096；不能保证低于未知供应商TPM，不将账户余额与速率配额混为一谈。
